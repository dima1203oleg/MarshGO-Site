## 4. Середовище виконання

### 4.1 Як підняти продукт для вимірювань

```
cd <worktree>/MarshGO-Site
API_PROXY_TARGET=http://127.0.0.1:3012 \
VITE_MAP_STYLE_URL=https://tiles.openfreemap.org/styles/bright \
VITE_MAP_TILE_URL=https://tile.openfreemap.org/{z}/{x}/{y}.png \
VITE_MAP_TILE_ATTRIBUTION="© OpenStreetMap contributors" \
  npx vite --host 127.0.0.1 --port 3000
```

- Без `VITE_MAP_TILE_URL` застосунок ** документально** показує «Базові тайли карти не налаштовані» —
  це fail-closed поведінка, **а не дефект**. Не чинити кодом. (Самопоправка з `AUTHENTICATED_FIRST_TOUCH.md` §4.)
- Гостьовий вхід: `#login-email` / `#login-password`; реєстрація: `#register-name` / `#register-email`
  / `#register-password`, submit `Зареєструватися`. Тест-акаунт — **самореєстрація через UI**; пароль тримати
  у тимчасовому файлі поза репо (`/tmp/...`, chmod 600), в коміт — жодного рядка з паролем.
- Поля маршруту: combobox-и з `aria-controls="route-place-origin-list"` / `route-place-destination-list`;
  вибір — клік по `[role="option"]`. Доступне ім'я combobox походить від `<label>` («Звідки»/«Куди»),
  тому `getByRole('combobox', {name:'Місто відправлення'})` **таймаутиться** — не вважати це дефектом продукту.
- Кнопка пошуку — `form button[type="submit"]` з текстом `Знайти маршрут` (у offer/demand-формах свої
  `Знайти`; помилковий клік вимірює не той флоу).

### 4.2 Вимірювальна дисципліна

Кожне твердження про дизайн має бути зняте одним із: (a) `file:line` у коді; (b) `getComputedStyle` /
`boundingClientRect` у живому DOM; (c) PNG-кадр. **Пробус теж валідувати перед вердиктом**: неправдоподобна
швидкість, однорідна порожнеча, «100 % перекриття», PASS на «порожнє == порожнє» означають зламаний пробус,
а не продукт. Два вже зафіксовані хибні пробуси (детектор шторки ловив повноекранний контейнер; «перекриття»
рахувало кнопку-контейнер картки) — не реанімовувати.

### 4.3 Правило єдиного письменника (найважливіше для агентного режиму)

`src/index.css` і `ProductionMarketplace.tsx` — по дві тисячі рядків на файл. **Паралельні агенти в один
файл = гарантований конфлікт.** Тому:

1. Файли-моноліти править **рівно один** агент одночасно; решта читають.
2. Хвилі W1 → W2 → W3 → W4 → W5 → W6 виконуються **послідовно** (W7/W8 — окремо, див. §6).
3. Усередині хвилі під-задачі паралельні лише за умови неперетину файлів; перетин = послідовно.
4. Кожен PR хвилі ребейзиться на актуальний base **до** пушу, конфлікти розв'язуються, а зміни не скасовуються.

## 5. Конфлікти: **рішення приймає власник, не агент**

Argon зупиняється й запитує, якщо натрапляє на будь-що з §5. Самовільний вибір = перероби.

### 5.1 Кількість snap-станів панелі результатів
Канонічний код: **3** стани, контракт підтверджений виміром (253/317/672 px на 844 px в'юпорту).
Пропозиція токенів: `sheetSnap: [0.12, 0.34, 0.64, 1.0]` — **4** стани.
Це зміна жестового контракту, не стилів. **Потрібне рішення власника:** 3 (безпечно) чи 4 (нова поведінка + нові тести).

### 5.2 `--mode-*` (кольори категорій транспорту) заморожені
D-12: `--mode-bus` = `--mg-blue` = `#1687FF` — автобус і брендовий акцент збігаються піксель-в-піксель.
Правило: `--mode-*` **не чіпати**; колір автобуса змінюється лише за окремим рішенням власника,
бо це впізнаваність 12 категорій і канонічна дошка. Правильна перша дія замість D-12 — прибрати другий бренд
(§6 W1), а не перекрасити автобус.

### 5.3 Хто володіє `src/index.css`
Відкрите рішення №3 із `FEATURE_PARITY_AND_PR_CONFLICTS.md` §10. До відповіді — жодного PR, що переписує
токен-шар.

### 5.4 Доля невлитих PR і base для наступних PR
Рішення №1, №2, №4 із того ж §10: 11 із 27 дефектів уже правляться невлитими PR; PR #48 проти #43/#46;
 zombie-PR. Argon **не закриває й не rebase-ить чужі PR**. Перед задачею — звірити, чи дефект уже правиться
 відкритим PR; якщо так — задача скасовується з записом «вже в PR #NNN».

### 5.5 Базиси візуальної прийомки
Базиси зняті в **гостьовій** зоні; авторизованих — 5 кадрів. Рішення №5 §10 (перенести базиси в
авторизовану зону) впливає на те, що взагалі можливо порівняти PNG↔PNG.

## 7. Правила реалізації (універсальні для всіх хвиль)

1. **Токен-first.** Ніяких нових сирих hex у `.tsx`; жодного нового `!important`; жодного `style={{}}` там,
   де існує токен. Токен відсутній → додати токен у W1-шар, а не валіти літерал.
2. **Нічого не втрачаємо.** Кожна реалізована функція лишається працюючою. Якщо стиль правиться через
   перекриття — перевірити обробники подій, aria, клавіатурні шляхи й live-області.
3. **Не вигадувати дані.** Немає ETA — немає ETA; немає тарифу — «Тариф невідомий»; немає доступності —
   пояснення. Жодного mock, виданого за live. Картки й кадри демо-даних — з міткою «ДЕМО · НЕ LIVE».
4. **Мова.** Текст UI — український, у регистрі й термінології чинного коду. Локалізацію не «поліпшувати»
   мовчазно; L10n-правки — окремий список у PR-описі.
5. **Обсяг правки.** Якщо задача вимагає змінити файл поза своєю хвилею — зупинитись і сообщити, а не правити.
6. **Архітектура без рефакторингу-заради-рефакторингу.** Виправлення дефекту не супроводжується перекроєм
   сусіднього коду; спостереження про технічний борг — у замітки, не у diff.
7. **Жодних нових залежностей** (npm, CDN, шрифти, зображення ззовні) без окремого дозволу.
8. **Права-субагенти**: `marshgo-site-engineer` — Views/токени/теми; `marshgo-server-engineer` — тільки W8;
   `marshgo-release-auditor` — W9. Навички: дизайн → `marshgo-design-system`, анімація → `marshgo-motion-engine`,
   карта → `marshgo-map-motion`, сценарії PWA → `marshgo-web-ux`, тести/гейти → `marshgo-test-gates`,
   Git → `marshgo-git-safety`, ресурс → `marshgo-resource-control`.

## 8. Критерії приймання кожного PR

Обов'язковий блок у тілі PR (українською):

```
Хвиля / задача: ARG-x.y
Закриває дефекти: D-…
Затверджена концепція: <назва> + SHA затвердження/посилання на речення власника
Змінені файли: <список>
Гейти (фактичний запуск, не транскрипція):
  npm test         → tests N, suites N, pass N, fail N, skipped N
  npm run typecheck → вихід N
  npm run lint:all  → вихід N
Мірники до/після: hex <…→…>, <12px <…→…>, !important <…→…>, rounded-[…] <…→…>
Виміри: мінімальний розмір шрифту …, тач-цілі …, маркери поза в'юпортом …
Кадри: evidence/…/*.png (легка + темна, кожен змінений в'юпорт)
Статус: VERIFIED / PARTIAL / BLOCKED / NOT_TESTED — по кожному пункті окремо
Не зроблено свідомо: <список + причина>
```

- **PASS не оголошується без запуску.** Не переписувати числа з попередніх звітів.
- **Падіння не приховуються, тести не skip-уються.** Якщо тест «заважає» — це сигнал, що треба читати, а не вимкнути.
- **Піксельні порівняння рахуються PNG↔PNG**; JPG — лише перегляд, не диф.
- **Зовнішній доказ.** Те, що заявлено як «працює для користувача», перевіряється на фактичному зовнішньому
  HTTPS-хості (доказ: `marshgo-dima.shares.zrok.io`), а не лише на localhost. Локальний прев'ю ≠ доказ публічної роботи.
- **Стан інфраструктури перевіряти** (`lsof -nP -iTCP -sTCP:LISTEN`, `curl /readyz`) перед тим, як сказати «здорово».

## 10. Порядок звітності Argon назад власнику

1. **Готовність задачі** (коротко): ID, статус VERIFIED/PARTIAL/BLOCKED/NOT_TESTED, SHA, PR-посилання.
2. **Блокер або відміна** — негайно, одним реченням з фактом (наприклад «D-14 уже правиться у відкритому PR #46»).
3. **Після кожної хвилі** — оновлення `CODEX_PROGRESS.md` + RESUME BLOCK у `NEXT_ACTIONS.md` (кореневий
   репозиторій) з **фактичними** числами тестів. Не створювати нових статусних документів на хвилю.
4. Ніколи: «має працювати», «зазвичай так роблять», «я покращив». Лише: що зроблено, що виміряно, що не перевірено.

## 11. Зупинитись і запитати, якщо…

- концепція ще не затверджена письмово (або затверджено одну, а задача виглядає як інша);
- правка чіпляє `--mode-*`, канонічну навігацію, 12 категорій, порядок/склад екрана, бізнес-процес чи серверний контракт;
- потребуються нові залежності, видалення коду,зміни у `package.json`, `main`, `codex/*`, деплой;
- треба переписати чужий незакомічений файл або чужий PR;
- вимірювання дає неправдоподібний результат (див. §4.2) — спочатку пробус, потім вердикт;
- потрібен кадр-базис, якого немає в `evidence/` (не імітувати, не домальовувати).
