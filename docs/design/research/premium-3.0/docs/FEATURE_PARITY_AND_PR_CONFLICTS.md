# Маршрут паритету функцій і реєстр конфліктів PR (A0 · CP2)

**Базис.** `8d927e8` ( MarshGO-Site `main`, він же — задеплоєний образ
`marshgo/web:RC-2026-11-02-mainmerge.1`). Пін і ланцюг доказу — у
[`BASELINE_PIN.md`](./BASELINE_PIN.md).

**Навіщо цей файл.** Власник поставив два жорсткі обмеження: не втратити жодної
реалізованої функції і не перезаписати роботу інших агентів. Обидва виконуються
тільки тоді, коли відомо, (a) що реально живе в задеплоєному коді, (b) які відкриті
PR уже правлять те, що мій аудит вважає дефектом, і (c) які твердження про
«працює» я не можу зробити чесно. Це — єдине джерело таких відомостей для етапів
A1–A3.

**Метод і авторитет джерела.** Всі дані — лише читання (`gh pr view`, `gh api
compare`). Локальні remote-tracking-рефи **не є авторитетними**: перевірено, що
`refs/remotes/origin/qoder/v41-ui-20261101` локально вказує на `13a1106e`, а
GitHub для того ж PR повертає head `3f2c9be8`. Тому статус «чи влитий вміст у
main» скрізь знятий з API-операції `compare/main...<branch>` (`ahead_by == 0`
означає «вміст уже в main»), а не з локального `git merge-base`. Сирий вивід усіх
запитів — `../evidence/pr-register.txt` (скрипт
`../evidence/pr-register.sh`, відтворюваний).

**Позначки.** `VERIFIED` — підтверджено особистою перевіркою коду або живим
запитом. `PARTIAL` — підтверджено частину твердження. `NOT_VERIFIED` — не
підтверджено, не використовувати як факт.

### 2.1 Що це дає практично

- **Раніше поставлене умоваю «чекати влиття #43–#46, #40, #39» — уже частково
  безпредметне.** Вміст **#40 і #39 (і #37, #38, #35) фактично вже в `main` і в
  задеплоєному образі**; PR відкриті лише тому, що їхня *base*-гілка (`v41-ui`,
  `map-unconfigured-notice`, `site-vehicle-quality-badge`) не влита. Тобто
  чекати «поки вллється #40» — це чекати закриття формальності, а не появи функції.
- **#43 і #46 вже є всередині #48** (`compare/<вміст>...qoder/premium-8-surface-2`
  дає `behind=0`). Влити #43, потім #46, потім #48 — тричі перенести той самий
  код. Реальний вибір — **#48 цілим** (він несе CP1+CP4 і ще +3 коміти), або
  #48 із навмисно закритими #43/#46 як дублями.
- **#45, #44, #49, #47, #50, #42 — поза #48** (`diverged`, `behind=1`): вони
  правлять той самий `src/index.css` і той самий `ProductionMarketplace.tsx`,
  которых #48 торкається масово. Конфлікт текстуальний майже напевно.

## 7. «Неможливо без брехні» — 10 пунктів з доказом і чесною заміною

Формула: **що хотілося б показати → чому це була б брехня → доказ → що показуємо
натомість.** Всі HTTP-числа — живі запити до публічного
`https://a602584pesfa.shares.zrok.io` 2026-11-03 (бандл підтверджено:
`assets/index-Ci-jmXW8.js`, 757 185 B, sha256 `eeae08878658e7f5…`).

**Б-1. Живий результат пошуку маршруту на скриншоті.**
`POST /api/v1/journeys/search` → **401** для guest. Без автентифікації результатів
не існує.
*Замість цього:* базові знімки лише гостьових станів; будь-який «результат» у
макетах — позначений `MOCK`, з фікстури, і названий фікстурою.

**Б-2. Реальні транспортні засоби на мапі.**
Реєстр провайдерів (`/api/v1/mobility/operators`, 200) показує **7 записів, 4
увімкнені, 1 зі статусом `ACTIVE_LIVE` (zelectra), 0 з `location_count > 0`, 0 з
`api_key_configured = true`**. Єдиний «живий» провайдер не має ключа і має
`live_available_count = 0`.
*Замість цього:* Geometry-шар без машин; анімовані позначки — тільки в
синтетичному прототипі з підписом «синтетичні дані».

**Б-3. ETA й «через 3 хвилини».**
`GET /api/v1/transit/stops/{id}/arrivals` → **400**, `/api/v1/transport-regions` →
**404**, `/api/v1/catalog/regions` → **404**. Клієнтські типи
`TransitArrival`/`transportRegions` мають **0 викликань у `src/`** (D-23).
*Замість цього:* показувати `SCHEDULED`/`UNAVAILABLE` semantics, які й так
передбачені доменною моделлю; жодного числа ETA без `arrivalSource`.

**Б-4. MarshPass на екрані.**
Інваріант 29 canonical README: MarshPass лише для підтвердженої приватної
поїздки. `/api/v1/bookings` → **401**, `/api/v1/marshpass` → **404**.
*Замість цього:* композиція з дошки як макет, з явним «схема з канонічної дошки»,
не «так виглядає в застосунку».

**Б-5. Готівкова ціна в транспорті як справжня.**
`src/views/cashFare.ts` уже **є** в базисі (перевірено `git cat-file -e
8d927e8:src/views/cashFare.ts`), а серверна частина — у **невлитому Server #75**.
Тобто клієнт готовий, даних з API в продакшн-білді немає.
*Замість цього:* будь-яка ціна в макетах має нести `fareSource`; для огляду —
лише похідна/реєстрова позначка, не «ціна провайдера».

**Б-6. «Усі 12 категорій транспорту працюють».**
Канонічний список справді 12 (`src/domain/transportCatalog.ts:11-24`: bus,
marshrutka, trolleybus, tram, metro, carpool, taxi, train, bike, scooter,
carsharing, transfer; 4 групи). Але реєстр провайдерів покриває лише
`BICYCLE`, `SCOOTER`, `TRANSFER` і то з нульовими локаціями; `/transport/layers`
і `/mobility/availability` → **401**.
*Замість цього:* заявляти «12 категорій у таксономії UI», окремо — «N категорій
з перевіреним живим фідом: 0 на цьому середовищі».

**Б-7. «Темна тема невідрізняється» як виправлення, якого ніхто не почав.**
Насправді виправлення (D-07) уже є в #48. Було б нечесно притягувати це як
«мій» здобуток A3 так само, як і ігнорувати, що воно не влитe.
*Замість цього:* в A3 не чіпати dark-ramp; фігурувати лише те, що #48 не закрив
(§6: D-06, D-08, D-13-частково-light-вживання, D-15…D-20).

**Б-8. «Тепер з 60 fps / без затримок».**
На базисі немає жодного e2e- або перформанс-гейту в репо Site (§5, рядок `e2e/`),
а машина власника — 8 GB із одним важким процесом. Виміряти це чесно можна лише
власним харнесом і лише з числом.
*Замість цього:* у CP3/A3 кожен вимір — окремий JSON у `evidence/` із методикою;
без виміру — рядок `NOT_MEASURED`, а не речення про швидкість.

**Б-9. «WCAG AA пройдено».**
Існують лише вибіркові guard-тести контрасту в межах конкретних класів
(`tests/v41-contrast.test.ts` на базисі — про пари emerald/amber -600).
*Замість цього:* заявляти лише ті пари «текст/поверхня», які пораховані скритом,
із переліком пар; решта — `NOT_CHECKED`.

**Б-10. «iOS виглядає так само».**
iOS закріплено (`ad27b6f7`), але цей пакет не запускав симулятора і не робив
знімків; Capacitor-оболонка читалася лише як код.
*Замість цього:* iOS-рядки в усіх таблицях — `NOT_VERIFIED`, доки не буде
знімка симулятора з SHA білда.

**Б-11 (додаток, бо він дорогий). «Превʼю — це чиста збірка з `main` без
помилки».** Бандл підтверджений за OCI-лейблом (ланцюг у BASELINE_PIN §2), але
**моя локальна збірка `8d927e8` без змінних оточення не збігається з деплойнутим
файлом**: локальний `dist/assets/index-BuVAvBLO.js` = 755 790 B, деплойнутий
`index-Ci-jmXW8.js` = 757 185 B; у деплойнутому є литерали
`https://tiles.openfreemap.org/styles/bright` і
`https://tile.openstreetmap.org/{z}/{x}/{y}.png`, яких **немає ні в `src/`, ні в
`node_modules`** (перевірено вибірковим `grep -rl` по всьому дереву). Механізм
підміни — змінні з префіксом `VITE_` на момент `RUN npm run build`
(`ops/docker/Dockerfile.site:8`), і `ops/docker/Dockerfile.site` оголошує лише
`VITE_MAP_STYLE_MANIFEST_URL`, тож конкретні значення `VITE_MAP_STYLE_URL` /
`VITE_MAP_TILE_URL` у репозиторії **не зберігаються і мені невідомі**.
*Чесна заміна:* карти-базиси CP3 показують **те, що малює реальний продакшн-білд
(OpenFreeMap «bright»)** — обидва апстріми перевірені на доступність (200,
48 762 B і 200, 6 725 B); і одночасно фіксація: **порівнювати sha256 білду з
локального `main` без тих самих `VITE_*` — безглуздо**, будь-хто, хто перевіряє
провенанс хешем, мусить відтворити build-time env.
